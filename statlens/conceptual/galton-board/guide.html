Instructor Guide: Galton Board

Companion notes for the StatLens demo — the binomial distribution, assembled one ball at a time

Launch in Presentation Mode

Overview ~8 min

A ball meets n rows of pegs and goes right at each with probability p. The bin it lands in is the number of rights — so the pile that builds underneath is a Binomial(n, p) distribution being drawn in front of the class. The exact probabilities are overlaid in purple, scaled to the number of balls dropped, and the normal approximation can be switched on in orange.

Controls worth knowing. Rows of pegs is n; the p slider tilts the board. +1 and +10 animate, +100 and +1000 go straight into the bins (a hundred balls falling at once is a smear), and ▶ runs a steady stream. Changing n or p clears the board, because the earlier balls fell through a different experiment.

A run that works

  1. Drop one ball and narrate it: left, right, right, left … "we are flipping a coin at every peg." Ask what the bin number is counting before you say.
  2. Drop ten. Ask which bin will fill fastest and why. The usual answer is "the middle"; the useful follow-up is why — there are many paths to the middle and exactly one to each edge.
  3. +1000. The pile snaps onto the purple curve. That curve was there from the start; the balls are only finding it.
  4. Turn on the normal approximation at n = 20, p = 0.5. It lies almost on top of the exact values.
  5. Now set p = 0.15 and n = 10. The pile is visibly skewed and the normal curve is visibly wrong — it leans past zero and sits off-centre. This is the np ≥ 10 condition arriving as something students can see rather than a rule to remember.
Discussion question. There is exactly one path to the leftmost bin and exactly one to the rightmost, but thousands to the middle. Where do those path counts show up in the formula? Answer: they are the binomial coefficient — the pegs are literally building Pascal's triangle, and a bin's probability is "how many routes lead here" times "how likely each route is".

Honesty about the physics

This board is not a physics simulation, and that is deliberate. Each ball's bounces are decided by a seeded coin first and then drawn. Real Galton boards do not produce exact binomials — pegs are imperfect, balls spin, neighbours interfere — so a faithful physics engine would produce a pile that only resembles the curve beside it. If a student asks whether a real one would do this: nearly, and the gap is a nice question. It also means p can be set to anything, which no physical board can do.

What is honest is the motion: every hop is a projectile arc (constant horizontal speed, accelerating downward), the ball squashes where it meets a peg, and the whole thing is paced by the clock, so it runs at the same speed on any machine.
